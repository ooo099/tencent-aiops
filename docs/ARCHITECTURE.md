# 架构设计

## 为什么要做分片

单实例时，指标存在进程内存里（KV）。一旦部署多副本，问题立刻出现：

- 写入落到实例 A，查询打到实例 B → **查不到数据**；
- 每个实例各自维持异常检测基线 → **同一指标被判两次、告警重复**。

两种解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| 共享存储 | 所有实例读写同一个 Redis/时序库 | 引入外部依赖，多一跳网络 |
| **分片路由（本方案）** | 按指标名做一致性哈希，同一指标固定落同一实例 | 实例增减需要迁移分片 |

选择分片的理由：这个服务的状态是"最近窗口的热数据"，天然适合按 key 切分；共享存储会引入新的故障点，反而不"云原生"。

## 拓扑

```
                       ┌──────────────────────────────┐
  客户端 / 采集器 ───▶ │  router（无状态，可水平扩容） │
                       │  一致性哈希：metric → 实例    │
                       └───────┬──────────┬───────────┘
                               │          │
                 ┌─────────────▼──┐  ┌────▼───────────┐
                 │ aiosight-0     │  │ aiosight-1     │  ... aiosight-2
                 │ KV + 检测器     │  │ KV + 检测器     │
                 │ 分片 A          │  │ 分片 B          │
                 └───────┬────────┘  └───────┬────────┘
                         │                   │
                         └────────┬──────────┘
                                  ▼
                     Prometheus 抓取每个 Pod 的 /metrics
                                  ▼
                              Grafana
```

## 组件职责

| 组件 | 职责 | 是否有状态 |
|---|---|---|
| `aiosight` | 指标写入、异常检测、告警、AI 诊断 | **有状态**（内存 KV） |
| `router` | 按指标名路由到固定分片 | 无状态 |
| Prometheus | 抓取各实例指标，做跨实例聚合 | 有状态（TSDB） |
| Grafana | 可视化与告警面板 | 无状态 |

## 一致性哈希

- 每个后端生成 150 个虚拟节点，降低数据倾斜；
- 哈希用 SHA-256 取前 4 字节（FNV 对 `a0/b1/c2` 这类低熵短串雪崩性不足，实测会倾斜到 52%）；
- 实例加入/退出时只影响相邻区间，迁移量约为 `1/N`。

实测：1000 个指标 key 分布在 3 个实例上，每个实例占比 28%–39%（见 `internal/ring/ring_test.go`）。

## 扩缩容模型

- **router**：完全无状态 → 用 HPA 按 CPU 自动扩缩（2–10 副本）；
- **aiosight 分片**：有状态 → 用 StatefulSet 固定 3 副本 + PDB 保证滚动更新时至少 2 个可用；
- 如果要扩分片数，需要：新实例上线 → 双写迁移 → 切换路由 → 下线旧分片（本项目未实现自动迁移，文档中明确标注为已知限制）。

## 故障处理

| 故障 | 表现 | 处理 |
|---|---|---|
| 分片实例挂掉 | router 转发失败 | 返回 502 + 计数器 `router_upstream_errors_total`；由 K8s 重启 Pod |
| 大模型不可用 | 诊断接口报错 | 熔断 30s + 本地兜底分析（无密钥时也走兜底） |
| 流量突增 | 单实例 CPU 升高 | router HPA 扩容；分片实例靠 requests/limits 保护 |
| 日志写满磁盘 | 吞吐下降 | 已知瓶颈，后续改为异步批量 + 采样 |

## 已知限制（面试可以主动说）

1. 分片实例的**自动迁移未实现**，扩容需要人工双写；
2. 状态在内存，Pod 重启会丢历史窗口；
3. 告警只做了单实例冷却，跨实例去重需要引入统一的告警中心。
